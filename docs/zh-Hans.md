# deck 简体中文指南

deck 是用于管理终端 agent session 的原生 macOS 控制台。每张卡片都对应一个真实、持久的 tmux session；看板里的栏目是手工分组，名称、位置和顺序由你决定；实时状态不会移动卡片。

## 快速开始

从 GitHub Releases 下载 `.dmg` 并拖入“应用程序”即可。应用已内置 tmux，无需另行安装。首次创建项目时，默认栏目会按当前语言命名为“需要关注 / 进行中 / 队列中 / 已搁置”；创建后这些名称就是你的数据，切换语言不会改名。

- 点击“新建 session”进入 shell（项目设了默认目录/命令时，会在那个目录启动并发送一次该命令）。
- shell 回到提示符时，deck 会低频保存当前目录和一段有上限的纯文本输出；
  机器重启后重新打开卡片，会在该目录创建新 shell，并把旧输出直接放入同一
  pane 的 tmux 滚动历史；分界线以下是新的实时提示符。旧内容只会写到输出，
  不会作为输入重放，deck 也不会恢复进程、环境变量或 agent 画面。可在
  “设置 → Shell 恢复”中关闭或清除。
- 拖动卡片可更换栏目；点击栏目空白处可指定新 session 的位置。看板头只保留「＋ 新建 session ▾」：它的菜单里有现在新建、按时钟定时新建、收到 Slack 标记时新建，以及「项目默认值…」「已有自动化…」「模板…」三个管理入口（也可右键项目标签）；项目设了默认命令时多一项「仅新建 shell」；项目有自动化规则后，旁边会出现「↻ N 条自动化」直达入口。没有任何 session 的项目会在栏目上方显示一个起点提示。
- 双击标题可重命名，右键卡片可编辑说明或关闭 session。
- 用 ⌘D / ⌘⇧D 拆分窗格；关闭窗格不会终止 session。
- 点击 session 顶栏的麦克风，在本机把语音转成草稿，录音中也可直接清空、仅插入或发送：有文字时停止收音并处理点击时的草稿，空白时不做任何事；也可先停止转写，再编辑处理。每个 session 独立保留草稿、识别语言和目标绑定，切换后自动恢复，无需手动确认目标，发送时自动检查当前程序；录音中切换 session 会停止收音，并保留原 session 已显示的文字。默认底部面板，可切换浮动或右侧；切换布局保留录音、草稿和目标。草稿与布局不跨应用重启保存。原生录音需要受支持的 macOS 12+ 本地识别配置；没有云端识别回退。默认提供中文、英文、日文；可在「设置 → 终端与 session → 语音输入」调整常用语言和默认识别语言，设置会跨重启保存。只启用一种语言时隐藏草稿中的选择器；更改默认语言保留已有 session 的有效选择，移除正在录音的语言会等录音结束后再切换。「跟随系统语言」不代表自动识别口语。详情见[语音输入说明](voice-input.md)。
- 卡片的 ⏱ 面板放它的“列表”：按顺序稍后发送的 prompt，首行按时间到期，后续行等 session 满足各行静默条件再发；这不证明上一步工作成功。列表有两个可选字段：“不早于”某个日期时间（已过去的时刻会被拒绝，不会滚到明天）和“重复”（每 5 分钟到 4 小时，可限定每日时段，直到你删除、N 次或某个时刻）；重复列表到每个间隔把全部行再发进同一个 session。模板是保存好的列表，卡片和自动化都能用。
- 标准任务放在自动化里（「新建 session ▾ → 已有自动化…」），触发方式二选一：时钟（每天 / 每周几 / 每月几号）或 Slack 标记（在设置里连接 Slack 后，给消息打的表情反应）。触发时新建一张卡、启动命令、发送模板，每次都是新 session，但启动命令可能自行恢复旧上下文。自动结束仍依赖队列空、结束报告或无 hook 时前台 shell、连续三次轮询及查看保护；这些不能证明业务成功，也不保证旧结束报告属于末行。deck 没在运行时错过的时钟时刻，15 分钟内仍会启动（可选改为当天内），超过就记为“错过”、不建卡；暂停后恢复或改过计划的规则从那一刻起算。“安静”仅表示没有输出，不表示任务完成或正在等待输入。
- 若 deck 在发送期间停止，结果会显示为“无法确认是否已发送”。系统不会自动重试；请确认已发送，或在接受重复发送风险后手动重试。

列表与自动化规则可显式启用“每行发送后由我检查，再继续（包括末行）”；旧列表默认不变。每次送达后留下持久人工检查点，查看、长静默或 hook 的本轮结束都不会放行。确认只许可当时显示的下一行及目标；编辑、重试、目标变化会撤销尚未使用的许可。下一行仍受时间、静默、最小间隔与目标核对约束，其他列表可以交错。跳过是省略工作，取消不算已检查。重复列表每次迭代重新检查；已启用的自动化末行未检查时不会自动结束，规则开关只影响新运行。

执行计划与 agent 观察分开显示；投递和人工检查记录分别保留最多 200 条标识与时间，不存历史 prompt。首次启用会把相关数据及 settings 升为 schema v2，关闭开关也不降级；旧版拒读，不能直接回滚到不支持检查点的版本。详见[投递与检查点契约](scheduler-context-safety.md#human-inspection-checkpoints-c-v01)。

语言可在“设置 → 语言”中选择“跟随系统 / English / 简体中文”，无需重启。

## 更新通道

Stable 是默认更新通道，只接收正式版本。需要提前体验候选版本时，可在
“设置 → 更新通道”中选择 Nightly 并确认风险；Nightly 经过相同的签名和
Apple 公证，但仍可能不稳定。版本号旁会显示当前通道和短 commit，反馈问题
时请一并提供。

Nightly 与 Stable 使用同一个应用、`~/.deck` 数据和 tmux session，不能同时
运行。安装 Nightly 前请备份重要数据。切回 Stable 只影响之后的更新检查，
不会自动降级；如果当前 Nightly 版本更高，需要重新安装 Stable DMG，同时仍
须遵守 future-schema/data compatibility 规则。维护者流程、恢复方法和信任
边界见[发布通道说明](release-channels.md)。

## 文档维护方式

完整的安全、持久化、构建与发布规范以英文 [README](../README.md) 为唯一技术来源。本页维护中文入口、核心操作和容易误解的产品语义，避免复制整份规范后产生漂移。


### 设置与应用日志

设置按「通用与外观」「快捷键」「终端与 session」「集成与自动化」「数据与日志」
「关于与更新」分类，可搜索设置名称及说明。左侧分类和底部「完成」固定显示，
右侧独立滚动；较长说明可通过「了解详情」展开。

「数据与日志」显示当前应用日志大小，并提供「导出日志…」和「重置日志…」。
重置需再次确认，只清空 `app.log`，不创建备份，之后继续记录新日志。
已导出的日志、命令历史、Shell 恢复数据和运行中的 session 不受影响；
命令历史和恢复数据保留各自独立的清除入口。

## 跨项目待关注

侧边栏“待关注”汇总所有项目中已报告的输入请求与本轮结束未读对象，并显示原项目和栏目。打开 session 成功后才清除结束未读；已打开不表示已处理，输入请求仍保留到状态改变。返回会恢复待关注筛选与滚动位置。

看板保留手工分组与卡片状态；状态汇总与筛选集中在侧边栏“待关注”视图，看板不再重复展示入口和筛选栏。无有效 agent 状态时，近期输出或安静都不意味着程序已就绪。更新失败/不完整时保留并标明旧快照；过期或停止对象只定位原卡片。查看记录只在本次应用运行期间保留，不保证重启后的事件重放或未读续接。
