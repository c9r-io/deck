# Codex 长文滚动诊断与验证

2026-09-26；本地隔离 Deck、捆绑 tmux 3.7c、Codex 0.157.1。

## 已定位并修复：默认全屏滚动

Deck 的 tmux 初始化原本强制 `mouse off`。Codex 的
[`tui/tmux.rs`](https://github.com/openai/codex/blob/rust-v0.157.1/codex-rs/tui/src/tui/tmux.rs)
会读取这个选项，并将鼠标捕获设为 `DisabledByTmux`；其备用屏幕输入配置因此不请求鼠标事件。
默认全屏 Codex 有自己的可滚动 transcript；此前将问题概括为“默认全屏不保留历史”不准确。
`--no-alt-screen` 能绕开这个问题，但参数选择属于用户，Deck 不添加、建议替换或改写启动参数。

修复让 tmux 开启鼠标协商。Deck 通过 xterm 的公开 parser API 消费外层 tmux 的纯鼠标模式请求，
保留本地双击、三击和拖拽选择。真实滚轮携带单元格坐标，由后端按内层 pane 的当前状态分派：
选择／copy-mode 优先，否则向请求鼠标的应用发送协商后的 SGR、UTF-8 或 X10 事件，其余情况滚动历史。
输入权限检查、坐标夹限、每批最多 60 步及发送前的模式复查仍在后端执行。
没有应用名称判断、模拟方向键、修改 Codex 配置或升级终端依赖。

真实 GUI 验证：默认全屏 Codex 输出 `WHEEL-001` 至 `WHEEL-080`，真实 GUI 滚轮事件可上滚到开头、下滚到中段和底部；
`DRAFT-UNCHANGED` 草稿保持不变；双击单词仍正常选择。正常退出后，shell 编号历史也能上下滚动。
`--no-alt-screen` 的隔离 GUI 基线同样可滚动。

## 尚未解决：额外画面异常

此前隔离窗口的“画面停住”没有稳定复现，已有采样日志也不能证明 PTY 消费停止。
本次在退出 Codex、打印 100 行 shell 文本、上滚之后观察到一次持久的重复画面：多数行显示 `SHELL-085`。
底层 pane 原始文本正常；重新挂接后显示正确的 `062..086`，随后滚动正常。
原始 pane 捕获不等于 copy-mode 视口，因此这还不能判定错误发生在 tmux、xterm 缓冲区还是 WebView 绘制层。

临时加入公开缓冲区与 DOM 的分层观测后，没有再次捕获相同异常。临时界面已移除，未以强制刷新或重置掩盖它。
新增 `terminal-paint` WK 回归覆盖备用屏幕进入／退出、编号文本连续性、公开缓冲区与 DOM 一致性、
滚轮上下移动和重新挂接后的新输出。它已通过，但不能据此宣称这个间歇性问题已根治。
若再次复现，应在恢复前同时保留 copy-mode 视口、公开 xterm buffer、DOM 文本和截图，并记录完整输出流以供重放。

另一个已确认边界：快速中断可能使应用退出时未清理鼠标及备用屏幕模式。
此时 tmux 仍报告鼠标捕获，滚轮可能到达 shell。协议标志没有记录设置它的进程；
本次修复不猜测并清除这些状态。正常退出和应用关闭鼠标标志后的回退已验证。
已运行的 Codex 也可能缓存旧的 tmux 鼠标策略，直至重新进入／恢复终端界面。
