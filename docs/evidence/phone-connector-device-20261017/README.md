## 根因（已证实）

1. **交付链正常。** 运行中的 Mac 进程为 0.8.4（e41bf49）。现场截图里的提示文字只存在于 e41bf49 起的 iOS 源码。
2. **旧的「全部卡片概要」被如约保留。** 4 张卡片的保存 cmd 都为空，后端按契约拒绝输出、消息和便签，权限判断本身正确。
3. **缺陷在引导。**
   - 手机只有一句「请检查 Mac 上的 Phone Connector 共享范围」，桌面中文界面并没有这个词。
   - 范围说明藏在主机行的折叠区域里。
   - 桌面提示是静态的，从不说明当前范围缺什么。
   - 队列拒绝复用了同一句话。
   - 用户只能在离开电脑之后才发现限制，而此时无法补救。
4. **真机复现（R1）。** 已发布源码 1.0 (3) + 旧范围 + 空 cmd，列表与详情提示与现场截图逐字一致
   （`screens/old-build-*.png`）。

未证实：用户手机实际安装的 build（由截图文字推断），以及它连接的主机身份（未使用用户手机）。

## 前两轮为什么没发现

- 验收都在模拟器 + loopback + 新数据上进行，直接设置目标范围，从未走过「旧配置保留 → 用户自己找到设置」这条路径。
- 发布记录只证明 TestFlight 可用，没有观察到真实安装与实际连接的主机。
- 下列问题只有真机能暴露：
  - HTTP 层抹掉了 `URLError`，网络中断从未被识别。AppModel 测试用替身直接注入 `URLError`，所以测不到。
  - `waitsForConnectivity` 让停用的主机最长 45 秒看起来仍然在线。
  - 本地网络权限被拒时，系统报「已断开与互联网的连接」，方向错误。
  - 未共享时写下的草稿，授权后被误报「目标已变化」。
  - 设置说明在小屏上把卡片挤出首屏。

## 修改

**按设备信任**（经用户确认，第一层）

- Mac 设备行可「信任此设备…」（带确认，写明设备名、包含 Shell 历史，且不能向 Shell 输入）或「取消信任」（无需确认）。
- 新设备配对后，Settings 立即按名字提供信任。
- 被信任的设备获得「全部卡片输出和便签」级访问，**不改变全局范围**；其他设备沿用全局选择。
- 信任变更与范围变更走同一套栅栏：丢弃进行中的读取，结束该设备的未决命令，不重放。
- 所有读取（快照、输出、便签）与写入（直接消息、便签提交栅栏）都按发起设备解析范围。
- 外部输入普查和会话架构普查已同步更新，并加严：信任只对未撤销的设备生效；每次写入前按同一设备重新检查。
- 不新增 Shell 输入、无保存命令的排队，也不新增自动化或 first-send 权限。
- 标志存放在设备记录中（为 false 时省略）。旧版 Deck 读取时忽略它，效果是收窄权限而不是扩大。

**手机端**

- 共享范围导致的拒绝：
  - 顶部显示紧凑说明：主机名、「设置 → 远程访问」、「信任此设备」、只需一次、无需重新配对；
  - 「保持当前设置」可按主机和范围收起，跨重启保持，范围变化后自动恢复；
  - 小屏首屏仍能看到卡片；每张受影响的卡片只标「输出未共享」。
- 队列拒绝改为说明需要保存的启动配置。
- 主机行显示本机 app 版本与 build。
- 草稿在输入第一个字符时绑定目标；未确认目标时写下的草稿需要明确点「使用当前目标」。
- 网络与离线：
  - 只有配对请求等待网络；
  - 保留 `URLError` 类型，网络中断时保留并标记旧内容；
  - 连接不上时给出检查清单（Mac 唤醒 / Deck 运行 / 手机连接器 / 同一网络 / 本地网络权限），写明主机名或配对地址。
- 中文术语统一为「手机连接器」；相机被拒文案本地化。

**桌面端**

- 范围选择器下方动态说明当前范围，并指出可「信任此设备」。
- 显示「看板中有 N 张卡片的输出不会共享给未信任的手机」。
- 配对二维码旁说明配对后可直接信任这台手机。
- 设备行显示「已信任」、最近同步时间、应用 build：只在进程内存中，来自已认证快照请求的默认 User-Agent，不持久化、不写日志、不作为授权依据。

**兼容**

- 三种全局范围的边界不变，旧配置不升级，协议与 golden fixtures 不变。
- 旧客户端仍显示原来的泛化提示。

**测试与验收工具**

- 新增 `scripts/connector-device-acceptance.py`、debug smoke 模式 `connector-device`。
- 工程增加 `DECK_CONNECTOR_BUNDLE_ID` / `DECK_CONNECTOR_DISPLAY_NAME`，默认值即发行身份。
- smoke 故障触发时写一行封闭格式日志。

**Mac 端独立核对**

- 撤权前，主机日志恰好 2 条 `send-message`，均为 delivered；便签 add / edit / delete 各一次。
- Claude 会话记录：2 条提示、2 条拼接回复；屏幕上的回复各出现一次。
- 注入的 504 触发 1 次。
- 磁盘上的便签依次为：不存在 → 新增 → 编辑 → 删除。
- 主机就绪检查 b=15，包含配对二维码旁的说明与「N 张未共享」。
- 全局范围全程保持「全部卡片概要」；设备记录最终为已信任 + 已撤销（状态视图显示为未信任）。
- 延迟：信任到输出 3.6 s；取消信任 3.2 s；重新信任 5.2 s；停用 5.5 s；启用 5.2 s；撤销 4.2 s；回复 5.5 s / 7.6 s。
