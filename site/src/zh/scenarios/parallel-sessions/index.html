场景指南 · 本地终端工作

同时开着几个终端，怎样找到需要你处理的会话

一个 Agent 在审查改动，另一个在排查问题，旁边的 shell 还在跑测试。你可以用 Deck 把需要回头看的会话放到一处，再打开对应终端，判断接下来该做什么。

这里使用的是示例任务，并非实际操作录像。普通 shell 也能按这些步骤整理；Agent 状态报告是可选项。每个 Agent 或程序仍负责自己的工作，Deck 帮你找到现在值得查看的会话。

1. 给每项工作一张容易辨认的卡片

  1. 在 Deck 中选好项目，用 ＋ 创建会话，在终端里运行平时的命令或已经安装的 Agent CLI。第一次使用可先看入门步骤。
  2. 双击标题，把卡片改成便于辨认的名字，例如「审查改动」「排查问题」「运行测试」。其他工作各自新建会话。
  3. 用返回按钮回到看板，程序会继续运行。按自己的习惯把卡片放进栏目，状态变化不会自动移动卡片。

分成独立卡片后，每个会话更容易找到。Agent 状态对应的是该 session 当前 tmux 窗口的活动窗格，并不会汇总你手动拆分的所有 tmux 窗格里的 Agent。

2. 把重要卡片留在待关注中

点击卡片上的 ☆，即可持续关注。打开侧边栏的「待关注」，再选「人工关注」，就能跨项目找到这些卡片。跑测试的普通 shell 也可以这样关注，无需启用 Agent 集成。

星标记录的是「我还要回来看」，不表示程序正在等你、已经结束或运行成功。查看终端或重启 Deck 都不会清除这个标记，直到你主动取消关注。不需要继续跟进时再取消；如果卡片还有其他待关注原因，它仍可能留在列表中。

3. 按需接入 Agent 的状态报告

打开设置，找到你实际使用的 Claude Code 或 Codex 状态集成。两个开关默认关闭。启用前阅读确认说明：Deck 会在对应 CLI 的配置中添加 hook，原有的其他 hook 会保留。

接着在 Deck 会话里使用对应 CLI，观察是否收到状态。开关已开启不代表报告一定已经到达；覆盖范围还取决于 CLI 支持的事件和配置。其他 CLI 不会因此自动获得输入请求或本轮结束报告。

使用 Codex 时：已安装的 hook 可能仍需在 Codex /hooks 中审查并信任。共享后台服务可能让 Deck 无法把事件可靠归属到正确终端；缺少报告时，应按覆盖不足处理。输入请求 hook 也不能覆盖每一种提问或 MCP elicitation（交互询问）。

4. 按报告的事实决定先看哪里

在「待关注」中，先核对条目所属的项目和栏目，再打开会话。不同安装版本的名称可能略有不同，重点是区分它实际报告了什么。

看到的情况下一步怎么做
请求输入（或待输入）打开终端，阅读实际问题或权限选项。报告只说明 Agent 发出过请求，回复前先确认它此刻需要什么。
结束未读阅读结果，核实你关心的目标是否达到。本轮结束不等于任务完成或成功；Agent 或后台工作仍可能继续。
人工关注回看你主动保留的工作，包括普通 shell。以终端中的实际内容判断当前情况。
无有效状态、安静或近期有输出需要了解进展时打开终端。没有有效 Agent 报告时，有输出只说明存在活动，安静只说明一段时间没有输出。安静不代表已准备好接收输入。

终端成功连接并显示后，这次本轮结束才会标为已读。打开卡片不会替你回答输入请求，也不证明请求已经处理。如果你另外使用了带人工检查的 prompt 列表，查看终端也不会放行该检查点。了解检查后继续的操作。

5. 列表为空时，先确认没有漏掉信息

  • 没有条目：查看「无有效状态」和人工关注的卡片。待关注列表为空，不证明没有事情需要处理。
  • 没有 Agent 报告：核对相应集成和 CLI 配置，再直接查看终端。信号尚不可用时，可以先保留重要卡片的星标。
  • 旧快照或刷新失败：重试刷新。上次的信息可以作为参考，但不能当作当前状态。
  • 会话已停止或状态过期：定位原卡片，检查仍可查看的内容。找到卡片不代表进程已经恢复，更不代表任务已经完成。

处理后返回「待关注」，原来的筛选和滚动位置会恢复。已读记录只在本次应用运行期间有效；重启 Deck 后，不保证保留未读历史，也不保证补回漏掉的事件。保存下来的人工关注星标与这份临时已读记录是两回事。

离开终端视图时使用返回按钮。关闭卡片会结束它的会话，不要为了清掉未读结果而关闭卡片。机器重启或会话服务重启也可能结束进程。长时间运行工作前，先了解离开、关闭与恢复的区别。
