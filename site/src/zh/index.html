为什么需要 deck

不用在各个终端之间巡查。

几个独立任务同时运行时，你还要做别的事。反复切换窗口，只为看看有没有新问题、结果出来没有，或哪项工作该回头处理，很快就会变成负担。deck 把有依据的关注信息集中起来；每个 agent 和程序仍照常做自己的工作。

每个 agent 或 CLI

负责自己的工作

Claude Code、Codex 等工具自己安排步骤、执行任务、提问和申请权限；支持的状态集成会把有用的报告交给 deck。

deck

帮你决定先看哪里

「待关注」跨 session 汇总受支持的报告和你手动关注的卡片。deck 不推测任务含义、不判断是否成功，也不会凭猜测移动卡片。

产品边界

deck 不是另一个 agent。

它不提供模型或 AI 账号，不替代 shell，也不接管 agent 的计划和工具执行。它提供本地终端、看板、跨任务关注、安全的协调和可选集成。它无法判断任务是否成功，也不会根据推测的任务内容自动整理看板。

本地应用

本地工作，无需 deck 云端工作区。

deck 没有云服务、云账号，也没有托管任务的远端服务器。session 和应用数据都在你的 Mac 上。你运行的 CLI 可能连接自己的模型服务。可选的 Slack、手机 Connector 和 Secure Tunnel 集成会使用相应服务或私有网络；更新检查会连接 GitHub。

常见问题

我需要一直开着 deck 吗？

如果要定时发送 prompt 或启动自动化，deck 需要保持运行。退出 deck 后，原有 session 仍可继续运行；重启机器或后台 Shell 服务则会结束其中的进程。

查看指南 →

安静代表 agent 准备好了吗？

不代表。没有有效的 agent 状态报告时，琥珀色只说明 session 已有一段时间没有输出。启用 Claude Code 或 Codex 的状态集成后，还可以看到输入请求和本轮结束报告；但本轮结束也不代表任务一定成功。

查看指南 →

打开结果就会发送下一条吗？

如果开启了人工检查，仅仅打开结果不会让列表继续，还需要点击确认。没有开启人工检查的列表，则按原有的时间和目标条件发送，不受是否打开结果影响。

查看指南 →

需要另外安装 agent 吗？

需要。deck 已内置 tmux，但 Claude Code、Codex 等 CLI 需要自行安装和配置，账号及模型服务也由它们提供。已有的 shell、脚本和其他终端工具同样可以使用。
