几个独立任务同时运行时，你还要做别的事。反复切换窗口，只为看看有没有新问题、结果出来没有，或哪项工作该回头处理，很快就会变成负担。

真实的终端 session

每张卡片都是本机真实的终端 session，运行你自己的 CLI。tmux 已内置；退出 deck 后 session 仍在。

有报告才显示状态

启用相应的状态集成后，Claude Code 和用 --no-daemon 启动的 Codex 会报告输入请求和本轮结束。没有报告时，deck 只会说 session 安静，或者近期有输出。

卡片由你摆放

用项目和栏目整理 session。状态变化不会移动卡片。

26 秒真实演示

需要你时，找到正确的那个终端。

几个 agent 同时运行时，「待关注」汇总其中一个上报的输入请求。打开对应终端处理，再查看下一轮结果，最后回到其他工作。

  1. 「待关注」列出一个输入请求和两个未读的本轮结束。
  2. 打开正在等待的 session，回复它。
  3. 查看结束未读的结果。
  4. 回到看板。

谁负责什么

工作交给 agent，注意力交给 deck。

很多工具在帮你并行运行更多 agent。deck 的方向正好相反：agent 已经在管理自己的工作，而且越来越擅长；真正稀缺的是你在所有工作之间的注意力，deck 只管这一件事。它不提供模型或 AI 账号，用普通 shell 也一样可以。

事项你的 agent你deck
规划任务、调用工具、提问和申请权限
分支、worktree 和 PR
回复输入请求
判断工作是否成功
在看板上摆放卡片和栏目
让每个 session 在本机 tmux 中持续运行
跨项目汇总上报的输入请求和未读的本轮结束
你开启后，在你离开时发通知

deck 不做 headless 运行、agent 池或任务规划，不碰你的代码仓库，也不会替你批准任何权限。

可选的协调功能

把重复的跟进安排好。

用模板启动熟悉的工作，定时发送 prompt，或用 Slack 标记触发新 session。列表可以在条件满足时发送事先安排好的后续输入，也可以在每个步骤发送后等你检查。

工作怎么做，仍由 agent 或程序自己决定。

了解发送状态与处理方法 →
安静不代表程序已准备好。程序可能在计算、等待输入，也可能暂时没有动静。只看有没有输出，还无法判断它能否接收下一条 prompt。
已发送不等于已完成。prompt 发出去了、agent 结束了这一轮、结果经过了检查，是三件不同的事。
自动发送时，应用必须运行。可以关掉终端窗格，但列表发送和自动化启动仍需要 deck 在运行。

需要时再用。

普通的终端用法不需要下面任何一项。每种集成都要单独设置，各有自己的边界。

应用内

  • 分屏并排查看多个终端。
  • 语音输入在本机识别后，把确认的文字直接输入选中的终端；deck 不会替你按回车。
  • 模板与定时启动用同样的方式启动重复的工作。
  • 卡片暂存区把笔记和对应的 session 放在一起。
  • 本地翻译在 Mac 上把终端里的英文译成简体中文。默认关闭；语言包在你确认后下载一次。

其他工具

  • Slack频道规则收集匹配的消息；已保存的模板决定哪些内容进入 agent 队列。
  • 手机连接器在可直达的私有网络中，获授权的 iOS 配套应用可以操作符合条件的 agent 卡片和已保存的任务预设。
  • MCP 客户端逐个授权项目和目录。执行命令仍需在 Mac 上另外批准。
  • ChatGPT托管的 ChatGPT 可以通过可选的 Secure Tunnel 接入。

本地应用

工作留在你的 Mac 上。

deck 没有云服务、云账号，也没有托管任务的远端服务器。session 和应用数据都在你的 Mac 上。你运行的 CLI 可能连接自己的模型服务。可选的 Slack、手机连接器和 Secure Tunnel 会使用相应服务或私有网络；可选的「本地翻译」在你确认后从 Mozilla 下载语言包；更新检查会连接 GitHub。

无需 deck 账号安装后即可使用。
本机语音识别录音在 Mac 上识别，没有云端备用。
本地数据应用数据保存在 ~/.deck，Slack 令牌保存在钥匙串。
MIT 开源源码公开，可自行查看和修改。

常见问题

我需要一直开着 deck 吗？

如果要定时发送 prompt 或启动自动化，deck 需要保持运行。退出 deck 后，原有 session 仍可继续运行；重启机器或后台 Shell 服务则会结束其中的进程。 查看指南 →

安静代表 agent 准备好了吗？

不代表。没有有效的 agent 状态报告时，琥珀色只说明 session 已有一段时间没有输出。启用 Claude Code 或 Codex 的状态集成后，还可以看到输入请求和本轮结束报告。Codex 只有用 codex --no-daemon 启动的 session 才能把状态报告给 deck；按默认方式在共享后台服务上运行时，卡片不显示 Codex 状态。本轮结束也不代表任务一定成功。 查看指南 →

打开结果就会发送下一条吗？

如果开启了人工检查，仅仅打开结果不会让列表继续，还需要点击确认。没有开启人工检查的列表，则按原有的时间和目标条件发送，不受是否打开结果影响。 查看指南 →

需要另外安装 agent 吗？

需要。deck 已内置 tmux，但 Claude Code、Codex 等 CLI 需要自行安装和配置，账号及模型服务也由它们提供。已有的 shell、脚本和其他终端工具同样可以使用。 查看指南 →
