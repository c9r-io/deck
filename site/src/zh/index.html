无需逐个读 pane，也能看见活动

绿色表示最近有输出，琥珀色表示安静，灰色表示停止。信号刻意保持简单——由你决定接下来关注什么。

有清晰边界的 scheduled prompt

排队执行，也能解释发生了什么。

把 prompt 安排到稍后发送，在安静一段时间后串联，或按周期重复。deck 记录发送状态，并让不确定结果保持可见。

检查上下文发送前重新检查 tmux server、session、window、pane、process generation，以及在可知时的前台 executable。
安静不等于 READY安静的 session 可能在等输入、运行无输出任务或什么也没做。deck 不读取终端内容来判断。
应用必须运行队列可以跨重启恢复，但 scheduled prompt 触发时 deck 必须打开；底层 tmux session 则独立存活。

Local-first 就是留在本地

你的终端不是遥测数据。

deck 的价值来自看见本地 session，而不是把它们发送到别处。

无需账号没有登录或云工作区。
终端内容不上传Prompt 和输出留在你的 Mac。
数据可检查状态以本地 JSON 保存在 ~/.deck。
MIT 开源可以阅读、构建、修改和审计源码。

常见问题

deck 做什么，也不做什么。

deck 会上传代码、prompt 或终端输出吗？

不会。deck 没有账号或云工作区，终端内容留在你的 Mac。这个 landing page 第一版也不包含分析或第三方脚本。

退出 deck 后 session 为什么还在？

deck 运行一个私有 tmux server。关闭应用只会让终端视图 detach，不会停止 tmux session；关闭卡片或退出其 shell 才会结束 session。

琥珀色表示 agent 正在等我输入吗？

不表示。琥珀色只说明 session 至少 15 秒没有输出，是查看线索，不代表 deck 理解了 agent 状态。

支持哪些 CLI？

任何可以在 macOS 终端内交互运行的 CLI，包括 Claude Code、Codex、OpenCode、构建工具、shell 和你自己的脚本。

为什么不通过 Mac App Store？

deck 使用 Developer ID 直接分发，使终端和 tmux 集成无需为 App Store sandbox 重新设计。Release 已签名、公证，并支持应用内更新。

支持哪些 Mac？

当前版本支持 Apple Silicon Mac，暂不支持 Intel Mac。
