原生 macOS · Apple Silicon

给本地终端
加一个管理界面。

方便你同时管理更多 agent。

deck 是本地终端外面的一层界面。你可以把它当作普通终端，照常运行命令、脚本或 CLI；同时开了多个任务时，用看板整理它们的 session。

deck 本身不是 agent，也不提供 AI 服务。你可以在里面运行自己习惯的 agent，就像在普通终端里一样。

deck 不提供云服务或云账号，也没有在远端运行任务的服务器。shell 和程序都运行在你的 Mac 上，tmux 已包含在应用中。

基本用法

当作普通终端用就可以。

不需要先学会自动化，也不一定要使用 agent。多开几个 session 时，再按自己的习惯整理。

打开一个 session

每张卡片对应一个本地终端。可以在里面运行 shell 命令、脚本，也可以启动已经安装好的 Claude Code、Codex 等 CLI。

给几个任务分个组

用项目和栏目把 session 放在一起，给卡片起个容易辨认的名字，点击就能回到对应终端。卡片的位置由你安排，不会按状态自动移动。

03 · 查看状态

看看哪些 session 有新情况

卡片会显示终端的活动状态。启用相应 agent 的状态集成后，「待关注」还能汇总它报告的输入请求和还没查看的本轮结束。是否完成任务，仍需要查看实际结果。

可选功能

也可以提前安排 prompt。

如果经常要分几次给同一个 session 发 prompt，可以写成列表，设置发送时间和等待条件。需要先看结果再继续时，可以开启每行人工检查。不开启这些功能，也能照常使用终端。

了解发送状态与处理方法 →
安静不代表程序已准备好程序可能在计算、等待输入，也可能暂时没有动静。只看有没有输出，还无法判断它能否接收下一条 prompt。
已发送不等于已完成prompt 发出去了、agent 结束了这一轮、结果经过了检查，是三件不同的事。
自动发送时，应用必须运行可以关掉终端窗格，但列表发送和自动化启动仍需要 deck 在运行。

分屏、补全和语音输入

多个终端可以分屏查看，常用命令有补全提示。想用语音输入时，可以先在本机转成草稿，编辑后再发送。模板、定时启动和 Slack 标记触发也都可以按需要使用。

本地应用

没有云端工作区。

deck 没有云服务、云账号，也没有托管任务的远端服务器。session 和应用数据都在你的 Mac 上。你运行的 CLI 可能连接自己的模型服务；可选的 Slack 集成会连接 Slack，更新检查会连接 GitHub。

阅读隐私说明 →
无需 deck 账号安装后即可使用。
本机语音识别录音在 Mac 上识别。
本地数据应用数据保存在 ~/.deck，Slack 令牌保存在钥匙串。
MIT 开源源码公开，可自行查看和修改。

常见问题

我需要一直开着 deck 吗？

如果要定时发送 prompt 或启动自动化，deck 需要保持运行。退出 deck 后，原有 session 仍可继续运行；重启机器或后台 Shell 服务则会结束其中的进程。

查看指南 →

安静代表 agent 准备好了吗？

不代表。没有有效的 agent 状态报告时，琥珀色只说明 session 已有一段时间没有输出。启用 Claude Code 或 Codex 的状态集成后，还可以看到输入请求和本轮结束报告；但本轮结束也不代表任务一定成功。

查看指南 →

打开结果就会发送下一条吗？

如果开启了人工检查，仅仅打开结果不会让列表继续，还需要点击确认。没有开启人工检查的列表，则按原有的时间和目标条件发送，不受是否打开结果影响。

查看指南 →

需要另外安装 agent 吗？

需要。deck 已内置 tmux，但 Claude Code、Codex 等 CLI 需要自行安装和配置，账号及模型服务也由它们提供。已有的 shell、脚本和其他终端工具同样可以使用。
