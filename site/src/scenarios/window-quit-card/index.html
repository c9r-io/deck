Practical guide · Leaving a session running

Close the window, quit Deck, or close a card?

Try all three on a disposable card and see what keeps running, what stops, and where to check queued prompts.

Try this with Deck 0.8.11 Stable on an awake Mac. You only need a normal shell, not an AI account or a real project. Use an ordinary card with no reminder, scratchpad, scheduled rule, or pending prompt.

1. Start a test card

Create a new session. At the shell prompt, paste the command below and press Return. It only prints the time, a process ID (PID), and a step number every five seconds for about two minutes. Note the first PID and step.

sh -c 'i=1; while [ "$i" -le 24 ]; do printf "%s pid=%s step=%s\n" "$(date +%H:%M:%S)" "$$" "$i"; i=$((i+1)); sleep 5; done'

2. Hide the window and keep Deck running

Use ⌘W or the red window button. Wait roughly ten seconds, click Deck in the Dock, and reopen the card. Look for the same PID with a higher step. The window was hidden, not the app quit, so Deck can still send queued prompts and start scheduled jobs when their conditions are met.

3. Quit Deck, then reopen the same version

Quitting affects all of Deck: first check that none of your other cards or rules needs Deck to send or start anything during the test. While the loop is still printing, press ⌘Q. After about ten seconds, reopen the same version of Deck and open the same card. The lines for the interval when Deck was closed should have the same PID and increasing steps. If the loop finished naturally before you could compare, rerun it and retry.

The terminal program can keep running, but Deck does not send queued prompts or start new automations while it is quit. For a real task, check the terminal output and the card’s ⏱ list separately. A supported Agent prompt may still be waiting for a new interaction after reopening. Read the waiting reason and check the terminal before sending manually. What to check when a prompt waits. Sleep or a Mac restart is not part of this test. See how scheduled runs handle missed time.

4. Save any output you need, then close only the test card

Check for unsaved work and pending prompts before clicking × on the test card in the Board. A plain card can close immediately. It disappears, its terminal session ends and its remaining queued prompts are cancelled. Don’t rely on shell recovery to recover output after closing a card. See when Deck asks before closing and what recovery can restore.
