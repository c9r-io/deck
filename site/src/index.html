Why deck exists

Stop patrolling every terminal.

Several independent pieces of work can be running while you do something else. Without one place to check, you switch tabs to find a question, a result worth reading, or a task you meant to revisit. deck gathers the attention you can actually observe across projects, while each Agent or program continues its own work.

Each Agent or CLI

Owns its work

Claude Code, Codex and other tools handle their own planning, execution, questions and permissions. They provide useful status when their integrations support it.

deck

Helps you choose where to look

Needs attention collects supported reports and your manual follow-ups across sessions. deck does not infer task meaning, decide success or move cards based on a guess.

A real 26-second demo

The right session comes back into view.

Several Agent sessions are running. Needs attention brings one reported input request into view; open the right terminal, respond, review the next result, then return to the wider work.

Optional coordination

Spend less attention on repeated follow-up.

Start known work from a saved template, schedule prompts, or use a Slack reaction to start a session. Lists can send already arranged follow-ups when their conditions hold, with optional human inspection after each row. The Agent still decides how the work proceeds.

Product boundary

deck is not another Agent.

It supplies no model or AI account and does not replace your shell, Agent planning or tool execution. It gives your local sessions a Board, cross-work attention, safe coordination and optional integrations. It cannot tell whether a task succeeded, and it never rearranges the Board from inferred task meaning.

Local application

Local work, without a deck cloud workspace.

deck has no cloud service, cloud account or remote server hosting your tasks. Sessions and app data live on your Mac. Your CLI may contact its own model provider. Optional Slack, Phone Connector and Secure Tunnel integrations use their named services or private network; update checks connect to GitHub.

Common questions

Do I need to keep deck running?

The app must be running for lists to deliver and automations to start. Sessions in private tmux survive quitting the app; a machine or service restart ends their processes.

Read the guide →

Does quiet mean the agent is ready?

Without a valid agent report, amber means the session has been quiet. Quiet is not ready. Enable the matching Claude Code or Codex status integration for explicit reports; a turn ending still does not prove task success.

Read the guide →

Will opening a result let the next prompt run?

Opening marks a reported turn ending as read. A list with human inspection enabled waits for your explicit confirmation, and then still checks its time and target conditions.

Read the guide →

Are agent CLIs included?

tmux is included. Install and configure your own agent CLI, or use any interactive command that works in a macOS terminal. Agent accounts and model access are managed by those tools.
