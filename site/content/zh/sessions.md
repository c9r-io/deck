# 离开、关闭与恢复

离开终端视图、退出应用和结束 session 是不同操作。离开前先确认你希望任务继续，还是结束它。

## 哪些操作会让工作继续

| 操作 | 对 session 的影响 | 对列表与自动化的影响 |
| --- | --- | --- |
| 返回看板、关闭分屏窗格 | 离开视图，不直接结束 session | 应用仍运行，投递可以继续 |
| 关闭应用窗口（红点或 ⌘W） | 窗口隐藏，session 继续 | 应用仍运行，投递可以继续 |
| 退出 deck（⌘Q） | 私有 tmux 中的 session 继续存活 | 应用退出期间不投递、不启动自动化 |
| 关闭卡片 | 结束该 session，移除卡片 | 取消该卡片的待发送列表 |
| 重启机器或后台 Shell 服务 | 原有进程结束 | 本地列表仍保存，重新运行 deck 后按当前条件重新检查 |

> 对选择了「关闭卡片」的自动化，离开窗格后可能满足自动结束条件。关闭窗格本身不终止 session，但也不承诺这类运行永远保留。[自动结束条件 →](/zh/guide/automations/#运行结束与检查)

## 要结束一个 session

关闭卡片会影响正在运行的 shell、agent 及其进程。0.6.5 中卡片角落的 × 和右键关闭会直接执行；session 内的关闭入口会先确认。结束前检查未保存的工作和待发送列表。

终端中的 Ctrl+D 由前台程序解释。只有在 shell 提示符等相应场景下，它才表示退出 shell；不要把它当作通用的「关闭 deck」快捷键。

Agent 退出通常只是回到 shell，并不等于整张卡片的 session 已经结束。

## 应用升级时

同一版本关闭后重新打开，会复用现有后台服务和进程。安装不同版本后，deck 可能要求重启后台 Shell 服务：空服务可以自动替换；仍有 session 时，会先列出影响并要求确认。

选择「稍后」可继续使用已有 session，待重启入口会留在侧边栏和设置中。确认重启会结束其中所有进程，不能把运行中的 agent 搬进新服务。

重开已停止卡片时，通常只在卡片目录启动 shell，**不会再次执行创建卡片时的启动命令**；尚未完成首次命令投递的卡片除外。请查看 agent 留下的恢复提示，由你决定是否恢复 agent。列表的自动投递启动路径可能会使用它所需的启动命令，应另行检查列表状态。

## 可选的 Shell 恢复

在「设置 → 终端与 session」中启用 Shell 恢复。它**默认关闭**：启用后，只有回到 shell 提示符时才保存当前目录及最多 256 KB 的近期纯文本输出，常见凭据格式会尽力脱敏。

机器或 tmux 重启后，打开卡片会在保存的目录启动新 shell，把旧文本放进同一窗格的滚动历史。明确的重启分界线下方才是新的实时提示符。

- 旧文本只写入输出，不会作为命令重放。
- 不恢复旧进程、任务、环境变量或 agent 的终端界面。
- 快照最多保留七天；关闭恢复会清除快照，也可在设置中手动清除。
- 脱敏不能保证移除所有敏感内容，启用前应考虑终端输出包含什么。

## 重开后没有按预期继续

先确认 deck 正在运行，再查看卡片终端和 ⏱ 面板。检查是否等待原程序、人工检查、静默条件，或显示投递不确定。不要为了“恢复”而反复重发 prompt。

原进程已经退出时，需要按 CLI 自身提供的方式恢复上下文；旧输出和保留的卡片不能代替进程恢复。
