# 离开、关闭与恢复

只是暂时不看终端，可以返回看板或关掉窗格；要结束里面的程序，则需要关闭卡片。下面列出了这些操作的具体影响。

## 哪些操作会让工作继续

| 操作 | 对 session 的影响 | 对列表与自动化的影响 |
| --- | --- | --- |
| 返回看板、关闭分屏窗格 | 离开视图，不直接结束 session | 应用仍在运行，可以继续发送 prompt |
| 关闭应用窗口（红点或 ⌘W） | 窗口隐藏，session 继续 | 应用仍在运行，可以继续发送 prompt |
| 退出 deck（⌘Q） | 私有 tmux 中的 session 继续存活 | 退出期间不发送 prompt，也不启动自动化 |
| 关闭卡片 | 结束该 session，移除卡片 | 取消该卡片的待发送列表 |
| 重启机器或后台 Shell 服务 | 原有进程结束 | 本地列表仍保存，重新运行 deck 后按当前条件重新检查 |

> 如果自动化设为结束后「关闭卡片」，关掉窗格后，它可能会按规则自动结束 session。关闭窗格本身不会结束程序，但会允许自动结束规则继续判断。[自动结束条件 →](/zh/guide/automations/#运行结束与检查)

## 要结束一个 session

关闭卡片会结束其中运行的 shell、agent 及其进程。0.6.5 中卡片角落的 × 和右键关闭会直接执行；session 内的关闭入口会先确认。结束前检查未保存的工作和待发送列表。

Ctrl+D 的作用取决于终端里正在运行的程序。在 shell 提示符下，它通常用于退出 shell；在 agent 或其他程序中，含义可能不同。它不是退出 deck 的快捷键。

Agent 退出通常只是回到 shell，并不等于整张卡片的 session 已经结束。

## 应用升级时

关闭后重新打开同一版本，deck 会继续使用原来的后台服务，程序也还在。安装不同版本后，可能需要重启后台 Shell 服务：没有 session 时会自动重启；还有 session 时，会先列出受影响的内容，请你确认。

选择「稍后」可继续使用已有 session，待重启入口会留在侧边栏和设置中。确认重启后，其中的程序都会结束，正在运行的 agent 无法转移到新服务中继续执行。

重新打开已停止的卡片时，通常只会在原目录启动 shell，**不会再次执行创建卡片时的启动命令**；如果卡片第一次启动时还没发出命令，则不在此列。可以根据 agent 留下的恢复提示，决定是否恢复原来的工作。如果卡片还有待发送列表，列表在自动启动 session 时可能会执行所需的启动命令，需要同时查看列表状态。

## 可选的 Shell 恢复

在「设置 → 终端与 session」中启用 Shell 恢复。它**默认关闭**：启用后，只有回到 shell 提示符时才保存当前目录及最多 256 KB 的近期纯文本输出，常见凭据格式会尽力脱敏。

机器或 tmux 重启后，打开卡片会在保存的目录启动新 shell，把旧文本放进同一窗格的滚动历史。旧记录和新终端之间会有一条重启分界线，线下方是当前可以操作的提示符。

- 旧文本只写入输出，不会作为命令重放。
- 不恢复旧进程、任务、环境变量或 agent 的终端界面。
- 快照最多保留七天；关闭恢复会清除快照，也可在设置中手动清除。
- 脱敏不能保证移除所有敏感内容，启用前应考虑终端输出包含什么。

## 重开后没有按预期继续

先确认 deck 正在运行，再查看卡片的终端和 ⏱ 面板。可能是在等原来的程序、等人工检查或静默条件，也可能无法确认上次是否已发送。找到原因后再处理，可以避免重复发送同一条 prompt。

如果原程序已经退出，需要使用该 CLI 自己的恢复方式继续工作。卡片和旧输出还在，并不表示原程序也恢复了。
