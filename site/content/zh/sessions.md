# 离开、关闭与恢复

只是暂时不看终端，可以返回看板或关掉窗格；要结束里面的程序，则需要关闭卡片。下面列出了这些操作的具体影响。

## 哪些操作会让工作继续

| 操作 | 对 session 的影响 | 对列表与自动化的影响 |
| --- | --- | --- |
| 返回看板、关闭分屏窗格 | 离开视图，不直接结束 session | 应用仍在运行，可以继续发送 prompt |
| 关闭应用窗口（红点或 ⌘W） | 窗口隐藏，session 继续 | 应用仍在运行，可以继续发送 prompt |
| 退出 deck（⌘Q） | 私有 tmux 中的 session 继续存活 | 退出期间不发送 prompt，也不启动自动化 |
| 关闭卡片 | 结束该 session，移除卡片 | 取消该卡片的待发送列表 |
| 重启机器或后台 Shell 服务 | 原有进程结束 | 本地列表仍保存；机器重启后重新检查，若在 Deck 中重启 Shell 服务，则受影响的列表会暂停，等待你恢复 |

> 如果自动化设为结束后「关闭卡片」，关掉窗格后，它可能会按规则自动结束 session。关闭窗格本身不会结束程序，但会允许自动结束规则继续判断。[自动结束条件 →](/zh/guide/automations/#运行结束与检查)

## 要结束一个 session

关闭卡片会结束其中运行的 shell、agent 及其进程。只有没有提醒或需要保留的暂存区时，卡片角落的 × 和右键关闭才会直接执行；session 内的关闭入口会先确认。暂存区里有内容时，也会先询问，关闭后这些笔记会随卡片删除。有提醒时，必须明确选择**取消提醒并关闭**，远程或自动关闭不能悄悄取消它。结束前检查未保存的工作和待发送列表。

Ctrl+D 的作用取决于终端里正在运行的程序。在 shell 提示符下，它通常用于退出 shell；在 agent 或其他程序中，含义可能不同。它不是退出 deck 的快捷键。

Agent 退出通常只是回到 shell，并不等于整张卡片的 session 已经结束。

Deck 确认普通卡片所属 shell 正常退出后，可以移除卡片并取消它的待发送列表。session 从列表中消失、服务丢失或被信号终止，都不构成这种证明，卡片会保持停止状态。MCP 来源卡片、需要保留的暂存区和提醒事项另有保留保护。提醒保护的是卡片，不是进程；结束提醒也不会放行此前被它阻止的自动移除。

## 应用升级时

关闭后重新打开同一版本，deck 会继续使用原来的后台服务，程序也还在。安装不同版本后，可能需要重启后台 Shell 服务：没有 session 时会自动重启；还有 session 时，会先列出受影响的内容，请你确认。

选择「稍后」可继续使用已有 session，待重启入口会留在侧边栏和设置中；完成重启前，Deck 不会新建 session。确认重启后，其中的程序都会结束，正在运行的 agent 无法转移到新服务中继续执行。

重新打开已停止的卡片时，通常只会在原目录启动 shell，**不会再次执行创建卡片时的启动命令**；如果卡片第一次启动时还没发出命令，则不在此列。可以根据 agent 留下的恢复提示，决定是否恢复原来的工作。如果卡片还有待发送列表，列表在自动启动 session 时可能会执行所需的启动命令，需要同时查看列表状态。

## 主动重启后重新进入 Agent 会话

使用前，先在**设置 → Agent 与通知**中启用对应 Agent 的会话重入观察。Claude Code 和带 `--no-daemon` 启动的 Codex 可能符合条件；Codex 还需要在 `/hooks` 中信任会话 hook。重启确认页的**重新进入 Agent 会话**会列出候选卡片，检查并勾选后再确认。Deck 会结束旧客户端，再为每张符合条件的选中卡片请求一次恢复到原来的确切会话，不发送任务 prompt，也不会保留旧进程。

默认策略不追加 bypass；对于以 bypass 启动的 Codex，会请求普通 profile，因为直接 resume 可能保留 bypass。Claude 原生恢复的其他状态仍由 Claude 决定。重新应用 bypass 需要本次重启单独明确选择，只作用于选中且启动配置已核实的卡片；如果运行中曾降低权限，应先阅读这项警告。

**重入后，受影响的列表仍保持暂停。** 先检查终端，再按需要恢复列表。Codex 的结果可能只是“已启动”，不能据此确认已进入会话或任务有进展；Agent 原有的待办工作也可能自行继续。若结果未确认，先检查已经启动的客户端，Deck 不会自动重试。对于没有重入或启动的卡片，结果页可能提供“插入恢复命令”，只填入文字，不替你提交。

## Shell 服务意外丢失后恢复

启用 Claude 会话重入观察后，Deck 会在本机记录所观察卡片对应的 Claude 会话。原 Shell 服务和客户端都已结束时，独立的**恢复中断的 Agent 会话**对话框可以列出这些卡片；先核对勾选项，再确认恢复。每张卡片只请求一次普通的确切会话 resume，不追加 bypass，也不发送任务 prompt。这不会恢复旧进程，更不能证明任务已成功继续。

确认或拒绝都会消耗本次列出的记录；确认恢复时，会在启动前先删除记录，因此不会再次提示或自动重试。未恢复的卡片需自行检查。此恢复不覆盖 Codex，也不覆盖使用 `CLAUDE_CONFIG_DIR` 启动的 Claude；它与下方的 Shell 输出快照不同。[本版本恢复机制](https://github.com/c9r-io/deck/blob/7f14b9b1e42a2f72230b421078b3a93cd8a02963/app/src-tauri/src/agent_reentry/recovery.rs)。

## 可选的 Shell 恢复

在「设置 → 终端与 session」中启用 Shell 恢复。它**默认关闭**：启用后，只有回到 shell 提示符时才保存当前目录及最多 256 KB 的近期纯文本输出，常见凭据格式会尽力脱敏。

机器或 tmux 重启后，打开卡片会在保存的目录启动新 shell，把旧文本放进同一窗格的滚动历史。旧记录和新终端之间会有一条重启分界线，线下方是当前可以操作的提示符。

- 旧文本只写入输出，不会作为命令重放。
- 不恢复旧进程、任务、环境变量或 agent 的终端界面。
- 快照最多保留七天；关闭恢复会清除快照，也可在设置中手动清除。
- 脱敏不能保证移除所有敏感内容，启用前应考虑终端输出包含什么。

## 重开后没有按预期继续

先确认 deck 正在运行，再查看卡片的终端和 ⏱ 面板。可能是在等原来的程序、等人工检查或静默条件，也可能无法确认上次是否已发送。找到原因后再处理，可以避免重复发送同一条 prompt。

如果原程序已经退出，需要使用该 CLI 自己的恢复方式继续工作。卡片和旧输出还在，并不表示原程序也恢复了。
