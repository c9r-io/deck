# 可选集成

不启用任何集成，Deck 也能当作本地终端使用。需要接入其他服务时，请在设置中分别启用，并先了解每种连接能读取或执行什么。

## Agent 状态

在**设置 → Agent 与通知**启用对应的 **Claude Code** 或 **Codex** 状态集成，便可在「待关注」查看报告的输入请求和本轮结束。Hook 回传固定状态词、窗格标识和不透明的交互 ID，不传 prompt 或输出。Codex hook 仍需在 `/hooks` 中审查并信任；状态不可用或无法归属，不代表没有工作需要你处理。[了解状态信号 →](/zh/guide/attention/)

同一设置分类中另有默认关闭的 **Pi 工作状态**。它只报告工作开始和一次交互结束，不报告输入请求。正在运行的 Pi 需要重启或执行 `/reload` 才加载观察扩展。Deck 无法可靠判断 Pi 是否可接收输入，因此不会向识别到的 Pi 自动投递 prompt，也不会自动重入；需要自行查看终端。

## Slack 表情标记与频道监控

个人 Slack 连接可以在**你自己**给消息加上指定表情时触发自动化。在**设置 → 集成 → Slack**配置连接，再到项目自动化中设置模板。启动工作时 Deck 必须运行；错过的表情事件可能由后续搜索补回。[设置表情自动化及其批准范围 →](/zh/guide/automations/#从-slack-标记开始)

**Slack 频道监控**是同一个 Deck Slack App 的可选能力：Bot token 独立，App token 共用。已有表情用户应更新并重装现有 App，粘贴新增 Bot token，再把 Bot 加入每个要监控的公开或私有频道；旧 Bot 的成员资格不会转移。规则需指定明确的频道 ID、允许的用户或 Bot ID，以及文字匹配条件。频道历史不会补抓，断线期间可能遗漏事件。

第一条匹配消息创建卡片、写入暂存区，并把已保存模板加入队列。后续匹配只增加笔记，从不自动成为 prompt。工作目录和命令来自你的规则，不由消息决定。命令必须以 `claude` 或 `codex` 开头，可带简单、不加引号的参数；不接受可执行文件路径、环境变量前缀或 shell 语法。模板每行必须以你自己的文字开头，不能以消息占位符开头。允许发送者只证明来源，不代表内容安全；Agent 可能按自己的权限执行文字中的要求。

规则里的**为未来符合规则的频道事件自动发送新运行的第一步**选项默认关闭。保存即同时允许范围内的未来新运行发送第一步，包括替换进入的外部内容，并接受启动输入风险。它支持 Claude，以及命令明确含有 `--no-daemon` 的 Codex。Deck 会先验证 Slack 连接再保存权限；验证失败时不保存规则，可重试。范围、目标或实际首步变化后需要更新权限。关闭选项会收回其覆盖的未发送首步，即使之后已观察到 Agent 交互也一样；已提交的发送可能继续完成。旧待处理事件不会因此追溯获权。每条后续步骤仍需**手动立即发送**，该选项也不批准 Agent 工具。[阅读固定版本的频道说明](https://github.com/c9r-io/deck/blob/7f14b9b1e42a2f72230b421078b3a93cd8a02963/docs/channel-monitor.md)。

## 卡片暂存区

暂存区保存任务笔记。可以编辑自己的笔记，再把选中内容的副本加入队列；收集到的频道条目保留原文。笔记和队列副本是不同内容，出现笔记不代表已经投递。后续频道消息不会自行发送。需要保留的暂存区会阻止自动移除卡片。手机可操作哪些笔记，取决于共享范围；队列操作仍要求受支持的已保存 Agent 命令，详见下方。

## 手机 Connector

可选的手机 Connector 通过可直达的私有网络，将独立的 iOS 配套应用与 Deck 配对。在**设置 → 远程访问**启用，检查配对二维码和设备列表。配对权限持续有效，直到你撤销。关闭 Connector 只停止监听，不撤销设备；要终止访问，请**撤销**设备或重置后重新配对。它不提供公网中继，也不保证后台送达。

默认范围只对已保存受支持 Agent 命令、且相应 Agent 正在前台运行的卡片开放输出和消息。选择所有卡片摘要，只增加看板元数据，不额外开放输出或笔记。在 Mac 上单独允许所有卡片的输出和笔记后，手机可读写现有及未来卡片的这些内容，包括 shell 历史，并可向当前前台的 Claude/Codex 发消息，即使 Agent 是手动启动的；始终不能向 shell 输入。

选择**信任此设备…**并确认，会让这台手机不受全局共享范围限制，获得上述较广访问，直到你取消信任或撤销设备。更新 Deck 不会扩大已有共享设置。扩大访问仍不允许在缺少受支持的已保存启动命令时操作队列，也不批准自动化。MCP 正在控制的卡片仍不开放给手机，直到你在 Mac 上收回控制。

手机上的“发送消息”是向当前符合条件的 Agent 直接输入的明确操作；先核对目标，前台程序匹配不代表已经就绪。改为加入队列的文字或笔记副本，则需在 Mac 上**手动立即发送**。配对或信任设备都不等于批准自动投递。「项目默认值」里的手机任务预设，可以分别批准固定后续步骤、接受首步启动风险，使用[自动化的相应选项](/zh/guide/automations/#首条输入与后续步骤的批准)，手机无法设置这些选择。修改涵盖的预设内容或目标，会使相关批准失效；撤销设备会收回它创建的任务里未发送步骤的权限。带首步权限的频道运行，不接受从手机加入队列的文字。Agent 可能因 prompt 以你的账号权限执行命令。[阅读固定版本的 Connector 说明](https://github.com/c9r-io/deck/blob/7f14b9b1e42a2f72230b421078b3a93cd8a02963/docs/connector.md)。

## Deck MCP 与 ChatGPT

**MCP 终端控制**默认关闭，入口在**设置 → 远程访问**。需要明确授权一个 client 的 Deck 项目和目录。结构化的列举、读取、搜索不会启动 shell；允许创建受管 session 是另一个选项；执行命令还需在 Mac 上给出有时限的独立批准。获批执行使用你的 macOS 账号权限，并非文件系统沙箱。可以在 Deck 设置里撤销 client。[阅读固定版本的 MCP 权限说明](https://github.com/c9r-io/deck/blob/7f14b9b1e42a2f72230b421078b3a93cd8a02963/docs/mcp.md)。

还可以单独、可撤销地委托 MCP client 触发你保存的 **Agent 移交**规则。允许创建终端不自动包含这项委托，也不允许任意命令。请检查规则的模板，以及首条输入和后续步骤的选择。[Agent 移交 →](/zh/guide/automations/#接收-agent-移交)

本机 STDIO 客户端可以直接使用 Deck MCP。托管的 ChatGPT 需要另装可选的 Deck Tunnel Helper 和 OpenAI 官方 `tunnel-client`；OpenAI Runtime API key 不由 Deck 保存。[阅读 Secure Tunnel 完整指南 →](/zh/docs/integrations/chatgpt-secure-tunnel/)

## 分享问题报告之前
