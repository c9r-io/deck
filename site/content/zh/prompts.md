# 安排后续输入

需要分几次给同一个 session 发 prompt 时，可以提前写成列表，设置发送时间和等待条件。若要先看过结果再发下一条，也可以开启每行人工检查。

## 创建一个列表

1. 打开 session，点击顶栏的 **⏱** 面板。
2. 新建列表，填入第一行 prompt，再从该列表底部追加后续行。
3. 根据需要设置「不早于」的日期时间，以及后续行的静默条件。
4. 查看执行计划，确认目标 session、下一行和等待条件。

第一行按设定的时间等待发送；之后的行还要等终端安静满设定的时长。「不早于」不能设为已经过去的时间，deck 也不会自动把它改成明天。同一个 session 每次发送一条 prompt，至少间隔一分钟；不同 session 的发送互不耽误。

> 这里的静默，是指终端没有新输出。程序可能仍在工作，也可能停在权限菜单上，并不一定能接收下一条 prompt。

例如，先让 agent 分析测试失败的原因，再提出修复建议。如果希望先确认分析没问题，再让它继续，就适合开启人工检查。仅靠静默时间，无法判断上一步的结果是否符合预期。

## 检查后再继续

在需要检查的列表中开启「每行发送后由我检查，再继续（包括末行）」。这个选项默认关闭，需要按列表分别设置。

每发完一行，列表都会停在人工检查点。查看终端里的结果后，点击 **「已检查，允许继续…」**，确认对话框中的下一条 prompt 和发送目标。这次确认只对显示的内容和目标有效；下一行仍会等待原定时间、静默时长和最小发送间隔。

- 打开窗格、收到本轮结束报告，或程序变得安静，都不会自动完成检查；等待权限回复时也一样。
- 如果编辑了下一行、进行了重试，或发送目标发生变化，之前还没用到的确认会失效，需要重新检查。
- 最后一行也需要检查。确认后，列表不再等待这次检查，但这一步本身不会结束程序。
- 跳过表示省略这项工作，取消也不算完成检查。

检查点会保存下来，重启应用后仍然等你确认。这个设置只对当前列表有效，**同一 session 中的其他列表仍可能发送 prompt**。多个列表之间没有先后依赖，不会自动等前一个列表完成。

## 重复与模板

开启「重复」后，整个列表会按设定间隔重新发送到同一个 session。间隔可选 5 分钟到 4 小时，还可以限定每天的生效时段、重复次数或截止时间。时段可以跨过午夜，例如 20:00–08:00。暂停不会清除设置；界面中的次数记录的是发送次数，不是任务成功的次数。

启用人工检查时，每次重复都需要重新检查。想要每次创建新 session，请使用[自动化](/zh/guide/automations/)，而不是重复列表。

列表的 **📋** 菜单可保存为模板或插入模板；插入的是副本，之后修改模板不会改变已有列表。

## 没有继续时怎么办

| 面板显示的情况 | 下一步 |
| --- | --- |
| 等待时间、静默或最小间隔 | 查看执行计划中的剩余条件，保持 deck 运行 |
| 等待人工检查 | 阅读当前结果，再从检查入口确认；仅打开终端不会继续 |
| 等待目标程序或上下文 | 查看对应终端，确认要接收 prompt 的程序已经回到前台，而不是停在 shell 或权限菜单中 |
| 发送失败 | 排除原因后重试，或选择跳过；该列表后续行不会越过失败行 |
| 无法确认是否已发送 | 先检查终端中有没有这条内容，再选择确认已发送或手动重试；重试可能重复发送，deck 不会自动重发 |
| 正在发送，暂时不能修改 | 等这次发送结束，再编辑、暂停或删除 |

发送前，deck 会再次检查对应终端和前台程序。如果能从启动命令识别要使用的程序，就会等它回到前台；无法识别时，会以兼容模式发送到同一终端，此时内容可能被 shell 当作命令执行，因此需要先确认终端里正在运行什么。如果发送时发现目标变了，当次发送会停止，后续尝试时再重新检查。

## 离开前看这里

**应用必须运行**，列表才能发送；对应的终端窗格可以关闭。面板会分别展示执行计划、发送记录和 agent 状态。计划如果已过期，其中的剩余时间也不再是实时倒计时。发送历史和检查历史各保留最多 200 条记录，只保存标识与时间；当前还没检查的内容会继续保留，方便核对。

首次启用人工检查会升级相关本地数据格式，关闭开关不会降级。需要退回旧版时，先读[更新与版本](/zh/guide/input-and-settings/#更新与版本)。
