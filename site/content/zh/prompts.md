# 安排后续输入

把之后要发给同一个 session 的 prompt 放进列表，让 deck 记住时间和顺序；需要判断结果的地方，可以选择每行检查后再继续。

## 创建一个列表

1. 打开 session，点击顶栏的 **⏱** 面板。
2. 新建列表，填入第一行 prompt，再从该列表底部追加后续行。
3. 根据需要设置「不早于」的日期时间，以及后续行的静默条件。
4. 查看执行计划，确认目标 session、下一行和等待条件。

首行按时间到期；后续行等待配置的静默时长。已经过去的「不早于」时间会被拒绝，不会被自动改成明天。同一个 session 每次只投递一条 prompt，至少间隔一分钟；不同 session 独立投递。

> 静默只表示没有输出。它不能确认程序已准备好、上一项任务已成功或权限菜单已退出。

例如：先请 agent 检查测试失败，再根据结果提出修复建议。如果第二行必须以你认可的分析为前提，应启用下面的人工检查，不要单靠静默时间建立依赖。

## 检查后再继续

在列表中显式启用「每行发送后由我检查，再继续（包括末行）」。已有列表默认不变。

每一行送达后都会留下人工检查点。回到终端阅读结果，再选择 **「已检查，允许继续…」**，核对对话框显示的下一条 prompt 和目标后确认。许可只对应这一次显示的内容与目标，下一行仍须满足时间、静默和最小间隔条件。

- 打开窗格、本轮结束报告、安静或权限等待都不会替你确认检查。
- 编辑下一行、重试或目标变化会撤销尚未使用的许可。
- 末行也需要检查；确认末行只解除最后的检查等待，不会自行结束进程。
- 跳过表示省略这项工作，取消也不算完成检查。

检查点会持久保存，应用重启后仍等待。这个开关约束所属列表，**同一 session 的其他列表仍可交错投递**。不要把多个列表的排列当成工作依赖。

## 重复与模板

「重复」会按间隔把整个列表再次发送到同一 session，可选择每 5 分钟到 4 小时、每日生效时段、次数或截止时间。跨午夜时段可以使用，例如 20:00–08:00。暂停保留设置，重复计数记录投递次数，不是成功完成任务的次数。

启用人工检查时，每次重复都需要重新检查。想要每次创建新 session，请使用[自动化](/zh/guide/automations/)，而不是重复列表。

列表的 **📋** 菜单可保存为模板或插入模板；插入的是副本，之后修改模板不会改变已有列表。

## 没有继续时怎么办

| 面板显示的情况 | 下一步 |
| --- | --- |
| 等待时间、静默或最小间隔 | 查看执行计划中的剩余条件，保持 deck 运行 |
| 等待人工检查 | 阅读当前结果，再从检查入口确认；仅打开终端不会继续 |
| 等待目标程序或上下文 | 查看卡片对应终端，让预期程序回到前台；不要向 shell 或权限菜单盲目投递 |
| 发送失败 | 排除原因后重试，或明确跳过；该列表后续行不会越过失败行 |
| 无法确认是否已发送 | 先检查终端；确认已发送，或接受可能重复后手动重试。deck 不会自动重发 |
| 正在发送，暂时不能修改 | 等这次投递结束，再编辑、暂停或删除 |

发送前 deck 会重新核对卡片拥有的终端和可识别的前台程序。已知启动命令时，会等待对应程序回到前台；无法识别时使用同一终端的兼容模式，输入可能被 shell 解释，安排前应检查目标。目标变化会阻止当次不匹配的投递，后续尝试可重新核对新一代 session。

## 离开前看这里

**应用必须运行**，列表才能投递；可以不打开对应窗格。执行计划、投递记录和 agent 状态是分别展示的，过期计划不能作为实时倒计时。历史记录分别最多保留 200 条投递和检查标识与时间；当前待检查点仍保留需要你核对的已发送内容。

首次启用人工检查会升级相关本地数据格式，关闭开关不会降级。需要退回旧版时，先读[更新与版本](/zh/guide/input-and-settings/#更新与版本)。
