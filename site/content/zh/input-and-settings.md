# 输入、设置与排障

用语音草稿和快捷键减少重复输入，在设置中调整工作环境，遇到问题时先保留内容再处理原因。

## 用语音准备 prompt

1. 打开目标 session，点击顶栏麦克风。草稿为空时会开始录音。
2. 选择识别语言，说出内容；可以停止后编辑，也可以在录音中直接操作当前已显示的文字。
3. **仅插入**把文字放入终端，不发送 Enter；**发送**插入文字并发送 Enter。处理非空草稿会先停止录音；空白草稿不会执行操作，也不会因此停止录音。
4. 发送前查看终端当前程序，尤其留意权限菜单、编辑器或 shell。发送只代表投递，不证明 agent 已接受任务。

Enter 在草稿中换行，⌘Enter 发送。清空会丢弃当前文字；成功发送会清除该 session 的草稿。每次录音最多五分钟，部分系统识别可能更早结束。

草稿、识别语言和目标绑定属于各自的 session。录音中切换 session 会停止收音，并保留原 session 已显示的文字；不会在新 session 自动开始录音。底部、浮动、右侧使用同一份编辑器，切换布局不会重启录音。

**未发送草稿与布局只在本次应用运行中保留，退出应用后不会恢复。** 需要保留的文字请先复制到你自己的文档。

## 语音无法开始或发送

录音需要受支持的 macOS 12+ 本地识别配置；macOS 26 的兼容设备和语言使用较新的本机识别引擎。首次使用可能需要下载 Apple 的语言资源，未准备好时按提示完成设置。没有云端语音回退。

| 情况 | 处理方式 |
| --- | --- |
| 麦克风权限被拒绝 | 按提示打开系统设置，允许 deck 使用麦克风，再主动开始录音 |
| 需要语音识别权限 | 在系统设置中允许语音识别，再重试 |
| 系统听写关闭 | 到「系统设置 → 键盘 → 听写」启用，再回到 deck 开始录音 |
| 语言不受支持或资源未就绪 | 选择受支持语言，按系统提示准备资源后重试 |
| 目标 session 已变化 | 先检查终端；下一次明确点击插入或发送会重新绑定并尝试一次 |
| 投递结果不确定 | 核查原终端，再使用「检查终端后重试」或清空。不会自动重发；原 session 被替换时，应核查并清空后重新撰写 |

权限或听写设置失败时，0.6.5 会给出对应系统设置入口。返回 deck 不会自动录音或发送。录音出错会保留已有文字，但它可能不完整。

在「设置 → 终端与 session → 语音输入」调整常用语言和默认语言，初始提供中文、英文、日文。只启用一种语言时隐藏选择器。「跟随系统语言」不会自动判断你说的语言。语言偏好跨重启保存，已有 session 的有效语言选择会保留。

## 常用操作

| 操作 | 入口或快捷键 |
| --- | --- |
| 新建 session | ＋ 新建 session / ⌘N |
| 横向、纵向分屏 | ⌘D / ⌘⇧D，或顶栏分屏按钮 |
| 选择已有 session 进入分屏 | 拖动侧边栏卡片到窗格边缘 |
| 收起侧边栏 | ⌘B |
| 复制与粘贴终端文字 | 拖动选择后 ⌘C / ⌘V |
| 跨屏选择 | 拖动到终端上边缘或下边缘并保持，继续选择历史内容 |
| 使用命令补全 | Tab 或 → 接受灰色建议；只记录 shell 命令，不记录 agent prompt |
| 打开路径或网页 | 点击终端中的已有本地路径或完整 HTTP(S) 链接 |

## 设置与日志

设置分为通用与外观、快捷键、终端与 session、集成与自动化、数据与日志、关于与更新六类，可以搜索名称和说明。

外观提供深色、浅色、跟随系统和高对比度，以及预设强调色；更改会应用到打开的终端窗格。界面语言可选择跟随系统、English 或简体中文。

「数据与日志」可以导出或重置诊断日志。重置需确认，只清空当前日志；命令历史、Shell 恢复数据、已导出的日志和运行中的 session 分别保留。清除历史与恢复数据使用各自的入口。

向 [GitHub 提交问题](https://github.com/c9r-io/deck/issues/new?template=feedback.yml)时提供版本、通道、复现步骤及预期行为。反馈通常公开，发送前检查截图或导出文件，去掉令牌、私有路径和真实任务内容。

## 更新与版本

本指南基于 **0.6.5** 的功能，适用于 **0.6.6 Stable**。Stable 是默认通道；Nightly 是主动选择的候选通道，功能和稳定性可能不同。设置中可以核对版本、通道和短 commit。

Stable 与 Nightly 替换同一个应用并共享本地数据和 tmux session，不能并排同时运行。切回 Stable 只改变以后检查的通道，不会自动把更高版本降级。同版本 Nightly 晋升为 Stable 时，安装包保持一致，无需为了通道名称重新安装；若已安装更高版本，则需先核对数据兼容性。

**人工检查的数据升级不会因关闭开关而撤销。** 首次启用会把相关队列和设置数据升为 v2，不支持它的旧版会拒绝读取。不要手改版本号或数据格式来绕过检查。需要回退时，先备份重要数据并核对目标版本兼容性；备份不等于恢复正在运行的进程。

完整维护说明见 [0.6.5 发布通道文档](https://github.com/c9r-io/deck/blob/caa944275d3313655df2585f4f552cecd9f10649/docs/release-channels.md)。应用数据与集成的范围见[隐私说明](/zh/privacy/)。
