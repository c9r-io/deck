# 判断是否需要关注

通过侧边栏「待关注」集中查看跨项目的输入请求和本轮结束未读，减少逐个打开终端确认的次数。

## 先启用相应状态集成

在「设置 → 集成与自动化」中，按你使用的 CLI 启用 **Claude Code** 或 **Codex** 的 Agent 状态。两个开关默认关闭。启用会在相应 CLI 配置中加入 deck 的 hook；确认前可查看说明，原有的其他 hook 会保留。

Hook 只报告固定状态词和 pane 标识，不发送 prompt 或输出。它们依赖 CLI 的事件支持；其他 CLI 仍可正常作为终端运行，但不会因此自动获得这些明确状态。

启用后，在 deck 的 session 中正常使用对应 CLI。若已有运行未报告状态，检查其配置是否已生效；不要把没有报告解释成“不需要关注”。

## 读懂每一种信号

| 你看到的信号 | 它说明什么 | 你可以做什么 |
| --- | --- | --- |
| 待输入 | 收到了 agent 的输入请求报告 | 打开终端，查看问题或权限选择 |
| 本轮结束未读 | 收到了本轮结束报告，尚未成功打开查看 | 阅读结果，决定下一步；它不证明任务成功 |
| 运行中 · agent 报告 | agent 报告正在工作 | 按需要等待或打开查看 |
| 近期有输出 · 无有效 agent 状态 | 观察到输出活动 | 作为活动线索，不能据此判断就绪 |
| 安静 · 无有效 agent 状态 | 一段时间没有输出 | 可能在计算、等输入或闲置，需要时查看终端 |
| 旧快照、过期或停止 | 当前信息不足或原 session 已停止 | 按提示定位原卡片，核实终端和连接状态 |

没有有效 agent 状态时，绿色表示最近 15 秒有输出，琥珀色表示安静。**安静不等于 READY，也不等于本轮结束。** 有效的 agent 状态优先于输出活动推断。

## 查看与返回

1. 点击侧边栏「待关注」，按需要选择筛选。
2. 查看条目上的原项目和栏目，打开对应 session。
3. 只有终端成功连接并显示后，本轮结束才标为已读。打开失败或仅定位过期对象不会清掉未读。
4. 处理完后返回，原筛选和滚动位置会恢复。

输入请求会保留到它的状态改变。**已打开不等于已处理**；这里的已读也不会放行列表中的人工检查点。[检查后继续的操作 →](/zh/guide/prompts/#检查后再继续)

## 没有条目或状态不更新

先查看「无有效状态」中的 session，再确认对应集成是否启用、CLI 是否仍在运行。轮询失败或数据不完整时，deck 会保留并标注旧快照；旧信息不能作为当前状态。

查看记录只保留在本次应用运行中，不保证应用重启后的未读续接或事件重放。CLI 的本轮结束报告也可能早于它的其他 hook 所要求的继续执行，因此重要结果仍需要你验证。
