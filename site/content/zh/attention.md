# 查看待关注的任务

侧边栏的「待关注」汇总各个项目的输入请求、结束未读、待处理投递和提醒事项。Deck 帮你决定先看哪里；工作究竟需要什么，仍要看程序和实际结果。

## 让卡片持续保留在待关注中

点击卡片上的 ☆，即可**持续关注**。★ 标记会让卡片保留在跨项目待关注列表中，直到你主动取消关注。查看结果、运行状态变化、移动栏目或重启 Deck 都不会清除标记。**人工关注**筛选包含这些卡片，无需启用状态集成。

同一卡片即使有多个关注原因，也只出现一次。取消星标只会撤掉人工关注；输入请求、未读结果、待处理投递、未查看的终端铃或到期提醒，仍可能让卡片留在列表中。看板上的卡片位置不会改变。

状态暂时不可用时，已保存的人工关注和提醒信息仍可参考。总数中的 **+** 表示已知数量的下限，不是所有 Agent 请求的完整统计。已停止或状态过期的条目仍能定位原卡片。

## 先启用相应状态集成

在**设置 → Agent 与通知**中，按你使用的 CLI 启用 **Claude Code** 或 **Codex** 的 Agent 状态。两个开关默认关闭。启用会在相应 CLI 配置中加入 Deck 的 hook；确认前可查看说明，原有的其他 hook 会保留。

Hook 回传固定状态词、窗格标识和不透明的交互 ID，不传 prompt、输出或路径。覆盖范围取决于 CLI 提供的事件。只有卡片当前 tmux 窗口的活动窗格提供 Agent 状态，不代表每个手动 tmux 分屏都被覆盖。其他 CLI 也可正常作为终端程序使用，但不会自动获得这些状态。

Codex 中，已安装的 hook 仍需在 `/hooks` 中审查并信任。新建交互式会话时，可选择 `codex --no-daemon` 作为兼容路径，但该会话不使用共享服务的连续性能力。Deck 会拒绝无法可靠归属到当前终端的事件。**Agent 状态未连接**表示尚无可靠观察；**Agent 状态不可用**表示已确认存在归属缺口。可点击**为什么？**了解原因。这两种提示都不会被虚构成输入请求，也不会自动算作紧急待关注。输入请求 hook 不能覆盖每一种提问或 MCP elicitation。

## 离席时收到提醒

在**设置 → Agent 与通知**中开启**离席时通知我**，默认关闭。Deck 不在前台时，可以针对 Agent 报告的输入请求和未读结束发出通知；这两种信号需要相应的 Agent 状态集成。

同一开关还覆盖列表里的**有投递待处理**，例如等待检查、投递不确定、发送失败、外部后续内容未获批准，或首条内容等待真实交互。这些是 Deck 自己的队列状态，无需 Agent 集成。普通的时间、静默和最小间隔等待不会通知。持续无法核实已保存批准时，约一分钟后可通知；这段等待不会批准或发送任何内容。

没有 Agent 状态时，程序仍可响终端铃。无人查看该卡片时，**终端铃**会使它进入待关注；离席时，上述开关允许发出通知。查看卡片前，反复响铃只计一次。终端铃只表示程序响了铃，不代表完成或成功。

开关开启时，Dock 按不同卡片汇总适用的输入请求、结束未读、待处理投递和未查看的终端铃；到期提醒独立计入。同一卡片只计一次，星标本身不会通知。通知只包含卡片标题、项目名和固定文字，不含 prompt、输出或路径。打开通知只会定位卡片，不会发送、重试或放行队列。

开启通知时，macOS 会请求授权。查看设置中显示的权限状态；若被阻止，到「系统设置 → 通知」允许 Deck。**播放提示音**是独立开关，默认关闭。专注模式和系统设置可能抑制横幅；保存设置不代表一定可见送达。

## 设置稍后返回的提醒

从卡片右键菜单或 Session 顶栏选择**设置提醒…**，保存前检查完整日期、时间和时区。已保存的日期标签可打开编辑器；**到期提醒**只显示已到期项，**全部提醒**还包含未来项。提醒不会发送输入、启动 session、移动卡片或维持程序存活。

提醒意图会跨应用重启保存。保存与 macOS 授权、注册是不同结果，编辑器会分别显示。系统通知不可用或未获授权时，可明确选择**仅在 Deck 内提醒**。提醒独立于「离席时通知我」开关。已注册提醒可能在 Deck 位于前台或已退出时通知，但仍受 macOS 送达条件限制；错过的提醒会留在 Deck 内，不补发过去的横幅。

查看卡片或关闭横幅不会结束提醒。可以改时间稍后再看，或明确结束提醒。未来和已到期提醒都会保护卡片免于自动关闭；手动关闭时需选择**取消提醒并关闭**。保护的是卡片，不是运行进程。[关闭与恢复 →](/zh/guide/sessions/)

## 读懂每一种信号

| 你看到的信号 | 它说明什么 | 你可以做什么 |
| --- | --- | --- |
| 请求输入 | Agent 报告有输入请求 | 打开终端，查看问题或权限选择 |
| 本轮结束 · 未读 | 一次交互结束，还没有查看 | 阅读结果；不代表任务完成、成功或 Agent 闲置 |
| 有投递待处理 | 某条队列内容需要人工处理 | 从 ⏱ 查看具体原因，再处理相应等待 |
| 终端铃 | 程序响了终端铃 | 打开卡片查看程序 |
| 到期提醒 | 你设定的返回时间已到 | 查看卡片，再结束或调整提醒 |
| 运行中 · agent 报告 | Agent 报告正在工作 | 按需要等待或打开查看 |
| 近期有输出 · 无有效 agent 状态 | 观察到输出活动 | 视为活动信息，不能据此判断是否能接收输入 |
| 安静 · 无有效 agent 状态 | 一段时间没有输出 | 可能在计算、等输入或闲置，需要时查看终端 |
| 旧快照、过期或停止 | 暂时无法获取最新状态，或原 session 已停止 | 按提示找到原卡片，查看终端和连接情况 |

没有有效 Agent 状态时，绿色表示最近 15 秒有输出，琥珀色表示安静。**安静不代表程序已准备好，也不代表本轮已结束。** 收到有效 Agent 状态时，Deck 优先显示该状态，不再只根据输出推测。

## 查看与返回

1. 点击侧边栏「待关注」，按需要选择筛选。
2. 查看条目上的原项目和栏目，打开对应 session。
3. 终端成功连接并显示后，这次本轮结束才会标为已读。如果打开失败，或只是找到了状态已过期的卡片，未读标记仍会保留。
4. 处理完后返回，原筛选和滚动位置会恢复。

输入请求不会因为打开终端就消失，只有状态改变后才会更新。**已打开不等于已处理**；标为已读不会放行列表的人工检查点。[检查后继续的操作 →](/zh/guide/prompts/#检查后再继续)

## 没有条目或状态不更新

先查看「无有效状态」中的 session，核对相应集成、hook 信任和 CLI 是否仍在运行。无法完整刷新时会保留注明「旧快照」的信息，旧信息不是当前状态。列表为空也不能证明工作都已完成。

已读标记不会跨 Deck 重启保留，也不保证保留未读历史或补回漏掉的事件；这和保存下来的星标、提醒事项不同。Agent 在报告本轮结束后仍可能继续后台工作，重要结果应自行核实。
