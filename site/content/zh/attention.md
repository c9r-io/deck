# 查看待关注的任务

有些任务在等回复，有些已经结束一轮、结果还没看。侧边栏的「待关注」把这些信息汇总在一起，方便查看各个项目的情况。

## 先启用相应状态集成

在「设置 → 集成与自动化」中，按你使用的 CLI 启用 **Claude Code** 或 **Codex** 的 Agent 状态。两个开关默认关闭。启用会在相应 CLI 配置中加入 deck 的 hook；确认前可查看说明，原有的其他 hook 会保留。

Hook 是 CLI 在特定时刻执行的回调。deck 的 hook 只回传固定的状态词和窗格标识，不传 prompt 或输出。Claude Code、Codex 之外的 CLI 也可以正常使用，但不会自动提供这些状态报告。

启用后，照常在 deck 的 session 中使用对应 CLI 即可。如果正在运行的 CLI 还没有报告状态，可以检查配置是否已生效。没有收到报告时，deck 无法判断它是否需要回复。

## 读懂每一种信号

| 你看到的信号 | 它说明什么 | 你可以做什么 |
| --- | --- | --- |
| 待输入 | agent 报告有输入请求 | 打开终端，查看问题或权限选择 |
| 本轮结束未读 | agent 报告本轮已结束，结果还没有打开查看 | 查看结果是否符合预期，再决定下一步 |
| 运行中 · agent 报告 | agent 报告正在工作 | 按需要等待或打开查看 |
| 近期有输出 · 无有效 agent 状态 | 观察到输出活动 | 可以了解程序是否有动静，但不能据此判断它是否能接收输入 |
| 安静 · 无有效 agent 状态 | 一段时间没有输出 | 可能在计算、等输入或闲置，需要时查看终端 |
| 旧快照、过期或停止 | 暂时无法获取最新状态，或原 session 已停止 | 按提示找到原卡片，查看终端和连接情况 |

没有有效 agent 状态时，绿色表示最近 15 秒有输出，琥珀色表示安静。**安静不代表程序已准备好，也不代表本轮已结束。** 收到有效的 agent 状态时，deck 会优先显示该状态，不再只根据输出推测。

## 查看与返回

1. 点击侧边栏「待关注」，按需要选择筛选。
2. 查看条目上的原项目和栏目，打开对应 session。
3. 终端成功连接并显示后，这次本轮结束才会标为已读。如果打开失败，或只是找到了状态已过期的卡片，未读标记仍会保留。
4. 处理完后返回，原筛选和滚动位置会恢复。

输入请求不会因为打开终端就消失，只有 agent 的状态改变后才会更新。**已打开不等于已处理**；如果列表开启了人工检查，标为已读后仍需要单独确认，列表才会继续。[检查后继续的操作 →](/zh/guide/prompts/#检查后再继续)

## 没有条目或状态不更新

可以先查看「无有效状态」中的 session，确认相应集成已经启用、CLI 仍在运行。如果暂时无法获取完整的新状态，deck 会保留上次的信息，并标注这是旧快照，供你参考。

已读记录只在本次应用运行期间有效。重启后，不保证保留原来的未读状态，也不会保证补回错过的报告。另外，CLI 可能先报告本轮结束，随后又因为其他 hook 的要求继续运行；重要任务是否完成，仍以实际结果为准。
