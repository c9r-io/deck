Automations

At each scheduled time deck creates a fresh card in the chosen column, launches the command and sends the template in order. A slot that comes due while the previous run is still on the Board is skipped. With “close when done”, the card is retired once every prompt is delivered and the agent reports its turn done (or the program exits).

A badge (emoji reaction) you put on a message in a connected service starts a new session here: one card in the column the rule names, launched with the rule’s command, then the rule’s template prompts with the message filled in. Cards are never moved automatically, and deck never writes back.

Tokens are kept in your macOS Keychain, never under ~/.deck, and are never shown again here. The user token finds your badged messages (search, about a minute behind); the app token hears new badges instantly. Only your own reactions count. There is no token without installing the app yourself: Slack has no OAuth redirect to a local app and no API that mints app-level tokens.
Templates belong to the chosen project. The first step is sent once the command is in the foreground; later steps follow in chain order. Placeholders: {{msg.text}} {{msg.from}} {{msg.where}} {{msg.link}}. A step that starts with a slash command hands the message to that skill.
One rule per badge. A message with several badges makes one card per rule; the same badge on the same message only ever makes one. Badges that already exist when a rule is added are left alone.
